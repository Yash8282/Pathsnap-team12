## A. Model Understanding

### A1. Why is LightGBM suitable for PathSnap?

PathSnap requires classifying GPS observation and road-segment candidate pairs as either the correct or incorrect road segment.

LightGBM is suitable because it is a gradient-boosted decision-tree algorithm capable of learning nonlinear relationships between engineered features. The dataset contains spatial and movement-related features such as distance from GPS observations to road segments, heading similarity, speed, road connectivity and contextual distances.

These features may interact in complex ways. LightGBM can learn such interactions without requiring feature scaling. It also supports efficient training on large datasets, making it suitable for the approximately 2.97 million training candidate pairs generated by the PathSnap pipeline.

### A2. Major strengths and limitations

**Strengths**
- Captures nonlinear relationships and feature interactions.
- Handles large tabular datasets efficiently.
- Does not require StandardScaler.
- Supports probabilistic predictions through `predict_proba`.
- Provides relatively fast inference.

**Limitations**
- Requires hyperparameter tuning to balance complexity and generalisation.
- Individual predictions do not guarantee geographically connected road sequences.
- Performance depends on candidate generation and the quality of reference labels.
- Gradient-boosted trees can overfit if their complexity is not controlled.

## B. Training and Configuration

### B5. Important hyperparameters and initial values

The following initial configuration was used:

| Hyperparameter | Initial value |
|---|---:|
| n_estimators | 300 |
| learning_rate | 0.05 |
| num_leaves | 63 |
| subsample | 0.8 |
| subsample_freq | 1 |
| colsample_bytree | 0.8 |
| random_state | 42 |
| n_jobs | -1 |
| max_train_rows | None |

All available training candidate pairs were used. No feature scaling was applied.

Five-fold GroupKFold cross-validation was performed using trip IDs as groups. This prevents observations from the same trip appearing in both training and validation folds.

**Training time per fold:**

| Fold | Fit time |
|---|---:|
| 0 | 10.68 s |
| 1 | 11.08 s |
| 2 | 10.42 s |
| 3 | 10.50 s |
| 4 | 11.46 s |

Mean fold fit time was approximately 10.82 seconds.

### B6. Loss function and optimisation objective

The classifier uses binary log loss (binary cross-entropy) to measure the difference between predicted probabilities and binary reference labels.

For a binary target:

L = -[y log(p) + (1-y) log(1-p)]

where:
- y is the reference class (0 or 1).
- p is the predicted probability of the candidate being the correct road segment.

LightGBM uses gradient boosting to minimise the training objective by sequentially adding trees that reduce prediction error.

## C. Experimental Results

### C7–C8. Student-test performance

The model was evaluated on all 10 student-testing trips.

| Metric | Result |
|---|---:|
| Observation-level Top-1 Accuracy | 0.8698 |
| Pair-level Macro F1 | 0.9322 |
| Log Loss | 0.0570 |
| Route Continuity | 0.8986 |
| Candidate Miss Rate | 0.000887 |

The model achieved approximately 86.98% observation-level Top-1 accuracy and 93.22% pair-level Macro F1.

The low candidate miss rate indicates that the reference road segment was usually present in the generated candidate set.

### Cross-validation performance

| Mean CV Top-1 Accuracy | 0.86332 |
| Mean CV Log Loss | 0.055997 |
| Mean CV Route Continuity | 0.91549 |

### C9. Overfitting or underfitting analysis

The final model's training pair Macro F1 was 0.9499, while its mean cross-validation Macro F1 was 0.9292.

The difference is approximately 0.0206.

This indicates a modest training-to-validation performance gap, suggesting some degree of fitting to the training data. However, the student-test Macro F1 of 0.9322 is close to the cross-validation result.

Therefore, there is no strong evidence of severe overfitting or underfitting in this experiment. The results suggest reasonable generalisation to the student-testing trips.

## Bayesian Optimisation Handover

LightGBM is a promising candidate for Bayesian hyperparameter optimisation because it achieved the highest cross-validation Macro F1 among the two models implemented in this experiment and trained quickly.

The following search space is proposed for Optuna TPE:

| Hyperparameter | Proposed search range |
|---|---|
| n_estimators | 200–700 |
| learning_rate | 0.01–0.15 (log scale) |
| num_leaves | 15–127 |
| max_depth | 4–12 |
| min_child_samples | 10–100 |
| subsample | 0.6–1.0 |
| colsample_bytree | 0.6–1.0 |
| reg_alpha | 1e-4–10 (log scale) |
| reg_lambda | 1e-4–10 (log scale) |

**Proposed optimisation objective:** Maximise mean five-fold GroupKFold Macro F1 on the training trips.

The final search space and trial count should be confirmed after the team's complete six-model comparison. The student-testing partition should only be used for final development-stage comparison, not for choosing individual trials.

## Conclusion

LightGBM achieved a cross-validation Macro F1 of 0.9292 and student-test Macro F1 of 0.9322. Its efficient training and strong classification performance make it a promising candidate for further optimisation and integration with the HMM/Viterbi route reconstruction stage.

Note: Reference labels are derived by aligning GPS observations to the supplied route. They should not be treated as independently verified ground truth.
